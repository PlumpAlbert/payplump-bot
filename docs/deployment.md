# Запуск в Docker / Komodo

Для обычного запуска нужны опубликованный образ, PostgreSQL и один приватный
файл с настройками. Ручной release workflow, manifest, отдельный pgpass,
пилотные списки и номера ревизий для этого не нужны.

## 1. Настройки

Возьмите `.env.example` как шаблон приватного файла на Docker-хосте. Не добавляйте
заполненный файл в Git. В Komodo укажите путь в `PAYPLUMP_ENV_FILE`; если файл
называется `.env` и лежит рядом с Compose на сервере, этот параметр не нужен.
Файл с ноутбука сам по себе на сервер не попадёт.

Обязательные группы настроек:

| Что | Переменные |
| --- | --- |
| PostgreSQL | `DATABASE_URL` либо `PGHOST`, `PGUSER`, `PGDATABASE` и нужные параметры `PGPORT`, `PGPASSWORD`, `PGSSLMODE` |
| Telegram | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_IDS` — числовые ID, не имена |
| Invoice Ninja | `INVOICE_NINJA_BASE_URL`, `INVOICE_NINJA_API_TOKEN`, `INVOICE_NINJA_PRODUCT_ID` |
| S-UI | `SUI_BASE_URL`, `SUI_API_TOKEN`, `SUI_INBOUND_IDS`, `SUI_SUBSCRIPTION_BASE_URL` |
| Оплата и календарь | `PAYMENT_PHONE`, `TZ`, например `Europe/Moscow` или `UTC` |

URL Ninja задаётся без `/api/v1`, URL панели — без `/apiv2` (установочный подпуть
панели сохраняется). `INVOICE_NINJA_PRODUCT_ID` — поле `id` продукта в API,
не `product_key` и не название тарифа.

По умолчанию бот сам читает из Ninja:

- валюту компании и её ISO-код;
- `inclusive_taxes` компании.

`PAYMENTS_CURRENCY_ID`, `PAYMENTS_CURRENCY_CODE` и
`INVOICE_NINJA_INCLUSIVE_TAXES` можно оставить пустыми. Явно заданные значения
сохраняются. Если Ninja не предоставляет необходимые настройки, сообщение
назовёт недостающее поле и параметр для ручной настройки.

`INVOICE_NINJA_VERSION` и `SUI_VERSION` не нужны: номер установленного релиза
не блокирует запуск. Несовместимые ответы API всё ещё обнаруживаются по реальным
полям и данным, а не по сравнению версии с одной строкой.

## 2. Telegram без публичного адреса

Оставьте `TELEGRAM_WEBHOOK_URL` пустым — используется long polling.
`TELEGRAM_WEBHOOK_SECRET` в этом режиме не нужен.

Webhook Invoice Ninja тоже необязательны. Оставьте
`INVOICE_NINJA_WEBHOOK_SECRET` и `INVOICE_LIFECYCLE_WEBHOOK_SECRET` пустыми,
если доставка не настроена: HTTP-маршруты выключены, сверка через API работает.
Если задаёте секреты, значения используются без изменений; допускается один
секрет для обоих маршрутов. Входящий заголовок должен совпадать с настройкой.
Webhook лишь ускоряет сверку, он не является доказательством оплаты.

## 3. Стек

В Komodo выберите корневой `compose.yaml` этого репозитория. Если используете
скопированный файл в homelab, его сервис должен получать те же настройки.
По умолчанию используется `ghcr.io/plumpalbert/payplump-bot:main`.
Для конкретного образа задайте `PAYPLUMP_IMAGE` с тегом или digest.
Для первого скачивания package в GHCR должен быть публичным либо Docker-хост
должен иметь доступ к приватному package.

Перед первым запуском:

- Убедитесь, что выбраны нужные панели: обычный сервис автоматически импортирует
  подходящих клиентов и начинает их обслуживание. Это не тестовый режим.
- Остановите прежний экземпляр. Один Telegram bot token — один процесс.
  При переносе используйте ту же БД с историей операций.
- Перед обновлением существующей БД сделайте резервную копию. Миграции
  применяются автоматически; для них нужны права создания таблиц и индексов.

Для самостоятельного запуска после подготовки настроек:

```sh
docker compose pull
docker compose up -d
docker compose logs --tail=100 payplump
```

В Komodo используйте его действия pull/deploy вместо запуска второй копии
из терминала. HTTP опубликован только на `127.0.0.1:8080` Docker-хоста
(порт меняется через `PAYPLUMP_HTTP_PORT`). Не публикуйте webhook-маршруты
без HTTPS и проверки отправителя.

## 4. Обновление

CI публикует образ, но не перезапускает Komodo. Чтобы применить новый `:main`,
нужны pull и redeploy существующего стека. Не создавайте второй стек с тем же
токеном. Readiness становится успешной после инициализации и проверки БД.

В логах ошибка чтения Ninja указывает этап и причину: например HTTP 401/403,
недоступное соединение, неверный ответ продукта или недостающее поле.
Не меняйте конфиг наугад из-за общего сообщения о Telegram.

Расширенные release/backup/recovery-инструменты остаются в
[release.md](release.md), [backup-restore.md](backup-restore.md) и
[operator.md](operator.md). Это не обязательные шаги обычного запуска.
